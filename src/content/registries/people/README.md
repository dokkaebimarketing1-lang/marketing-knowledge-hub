# 사람 레지스트리 정책

사람 레지스트리는 확인된 저자 정보만 보관한다. 기존 18개 문서처럼 저자를 확인할 수 없는 콘텐츠에는 이름, 팀, 직책을 추정하거나 임시 저자를 만들지 않는다.

## 파일 계약

한 사람마다 JSON 파일 하나를 둔다. 파일명은 `<id>.json`이며 파일 stem과 `id` 값이 반드시 같아야 한다.

각 레코드는 다음 필드를 사용한다.

- `id`: 변경하지 않는 고유 ID
- `name`: 검증된 표시 이름
- `role`: 검증된 역할 또는 직책
- `url`: 선택 필드. 검증된 공식 소개 페이지 URL
- `sameAs`: 검증된 동일 인물 외부 URL 배열. 없으면 빈 배열
- `status`: `active` 또는 `deprecated`

## 검증과 검수 상태

이름과 역할은 공식 프로필, 소속 조직의 공개 페이지처럼 출처와 동일 인물을 확인할 수 있는 자료로 검증한다. `url`과 `sameAs`도 해당 인물의 공식 페이지임을 확인한 뒤 기록한다. 근거를 확인할 수 없으면 사람 레코드를 만들지 않는다.

콘텐츠의 `reviewStatus: reviewed`는 `authorId`가 존재하고, 그 ID와 일치하는 검증된 사람 레코드가 있을 때만 허용한다. 사람 레코드가 없거나 검증이 끝나지 않았다면 `reviewed`로 표시할 수 없다.

## 기존 콘텐츠의 알 수 없는 저자

저자를 확인할 수 없는 기존 콘텐츠는 다음 값을 함께 사용한다.

```json
{
  "authorId": null,
  "reviewStatus": "human-review-needed"
}
```

`authorId: null`은 허용되는 상태다. 빈 문자열, 임시 ID, 가상 인물, 추정한 이름, 확인되지 않은 팀 명칭으로 이를 대체하지 않는다.
